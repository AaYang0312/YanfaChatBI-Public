# Schema RAG：BM25 对照评测

本次实验比较两种结构检索：优化前使用向量检索和带文本匹配过滤的向量检索；BM25 版使用独立的正文、表名 BM25 检索，并和原向量结果做 RRF 融合。两组保留同样的范围过滤、后处理和上下文预算。

| 指标（60 道合成盲测题） | 原版 | BM25 版 |
| --- | ---: | ---: |
| 首轮结构证据集齐率 | 59/60（98.3%） | 59/60（98.3%） |
| 平均 Schema 上下文大小 | 7,938 B | 6,857 B（−13.6%） |
| 检索与上下文组装 P95 | 102.26 ms | 102.24 ms |
| 单次生成的 SQL 在两份数据快照上都返回正确结果 | 27/60（45.0%） | 28/60（46.7%） |

两组在隔离环境使用同一批中文题目、28 张合成表、PostgreSQL 16.15 和 Qdrant 1.20.0。检索用 `qwen3-embedding:8b`，SQL 生成用 `qwen3:4b-instruct-2507-q4_K_M`。两组最多保留 10 个检索分块，Schema 上下文上限为 64 KiB。只有题目所需表和字段的详细信息确实进入首轮模型提示，才记为证据集齐。

P95 来自预热后交替执行的 5 轮评测，每组 300 个样本、单并发。计时包含目录读取、问题向量化、Qdrant 检索和上下文组装。SQL 用同一个模型生成一次，在只读数据库中和参考 SQL 的结果对比；第二份快照加入了专门识别漏聚合和并列排序错误的数据。

本次观察到上下文缩小、P95 基本持平。SQL 仅多答对 1 题，无法据此判断总体准确率是否提升。该实验也未测量生产流量、并发容量、多轮对话或工具补查。

真实 Qdrant 回归还验证了一个定向场景：向量相似度低于阈值时，独立 BM25 能找回用户明确提到的表，并保持聊天与索引代次隔离。部署设置见[配置参考](CONFIGURATION.md#7-嵌入与-rag)。
